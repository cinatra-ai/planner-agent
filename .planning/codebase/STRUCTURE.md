## Directory Purposes

**`cinatra/`:**
- Purpose: Cinatra platform sidecar assets — the canonical location for agent OAS and workflow BPMN files
- Contains: `oas.json` (OAS Flow 26.1.0 agent topology)
- Key files: `cinatra/oas.json`

**`skills/`:**
- Purpose: LLM skill definitions loaded by the Cinatra platform at agent runtime
- Contains: One skill subdirectory per skill; each contains a `SKILL.md`
- Key files: `skills/design-review-methodology/SKILL.md`

**`.github/workflows/`:**
- Purpose: GitHub Actions CI/CD pipelines for the extracted extension repo
- Contains: `ci.yml` (build + kind-gate), `release.yml` (release pipeline)
- Key files: `.github/workflows/ci.yml`

**`.planning/codebase/`:**
- Purpose: GSD codebase map documents generated by `/gsd-map-codebase`
- Generated: Yes (by GSD tooling)
- Committed: Yes (planning artifacts)

## Key File Locations

**Agent Definition (Entry Point):**
- `cinatra/oas.json`: Full OAS Flow 26.1.0 declaration — nodes, edges, inputs, outputs, LLM config

**Skill / LLM Methodology:**
- `skills/design-review-methodology/SKILL.md`: System prompt rules, output contract, review checklist

**CI Gate:**
- `extension-kind-gate.mjs`: Zero-dependency Node.js gate — exports `validateAgent`, `validateWorkflow`, `validateBpmnSanity`, `validateWorkflowPackageShape`, `runGate`, `parseArgs`; has a `main()` for direct CLI invocation

**Package Manifest:**
- `package.json`: `name: @cinatra-ai/planner-agent`, `cinatra.kind: "agent"`, `cinatra.apiVersion: "cinatra.ai/v1"`, `cinatra.dependencies: []`

**TypeScript Config:**
- `tsconfig.json`: Template config targeting `src/` (no `src/` exists — content-only extension); used by monorepo typecheck pass

**CI Pipeline:**
- `.github/workflows/ci.yml`: Classifies repo as source mirror vs. standalone; skips install/typecheck/test for source mirrors; always runs `npm pack --dry-run` and `extension-kind-gate.mjs`

## Naming Conventions

**Files:**
- Agent OAS sidecar: always `cinatra/oas.json` (platform convention)
- Workflow BPMN sidecar: always `cinatra/workflow.bpmn` (platform convention, not present here)
- CI gate: `extension-kind-gate.mjs` (kebab-case `.mjs`, self-contained)
- Skills: `skills/<skill-name>/SKILL.md` (kebab-case directory, uppercase SKILL.md)

**Directories:**
- Skills directory: `skills/` at repo root
- Cinatra assets: `cinatra/` at repo root (platform-mandated name)

## Where to Add New Code

**New review check (design rule):**
- Add the rule to `skills/design-review-methodology/SKILL.md` under "What to check"
- If the rule is deterministic (not LLM taste), it belongs in the monorepo's lint gate, NOT here

**New skill:**
- Create `skills/<new-skill-name>/SKILL.md`
- Register the skill's `agent_id` match in the `SKILL.md` frontmatter

**New input to the agent flow:**
- Add to `inputs` array in `cinatra/oas.json` (top-level and inside `$referenced_components.start`)
- Add a corresponding `DataFlowEdge` in `data_flow_connections` routing it to the `review` node

**Additional CI gate logic (for agent kind):**
- Add to `validateAgent(packageRoot)` in `extension-kind-gate.mjs`
- Banned primitive tokens go in `BANNED_PRIMITIVES` array; banned type hints in `BANNED_TYPEHINTS`

**No new TypeScript source files:** This is a content-only extension (no `src/` directory). Runtime behavior is defined entirely by `cinatra/oas.json` and `skills/`. Any TypeScript would require monorepo-side compilation.

## Special Directories

**`cinatra/`:**
- Purpose: Platform-mandated sidecar asset directory. Cinatra marketplace expects `cinatra/oas.json` for agents and `cinatra/workflow.bpmn` for workflows exactly here.
- Generated: No (hand-authored / tooling-assisted)
- Committed: Yes

**`skills/`:**
- Purpose: LLM skill definitions; matched to agents by `agent_id` in `SKILL.md` frontmatter
- Generated: No
- Committed: Yes

**`.planning/`:**
- Purpose: GSD planning artifacts (codebase maps, phase plans)
- Generated: Yes (GSD tooling)
- Committed: Yes
